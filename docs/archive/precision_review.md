# 아카이브: 정밀 검토 기능

## 요약

"정밀 검토"는 Conflict Board 이후 선택적으로 들어갈 수 있던 8단계 강제 흐름이었다.
포지션(매수/매도 검토)을 선택하면 먼저 반대 관점 근거를 체크박스로 확인시키고, 지지
관점을 보여준 뒤, Conflict Board를 다시 보여주고, 손절가·익절가를 기술적 지표 기반으로
자동 산출해 확인시키고, 결정 이유 메모(선택)를 받고, 최종 확인 후 매매일지에 기록하는
순서였다.

## 제거된 이유

Conflict Board 하나로 핵심 경험이 충분하다고 판단했다. 이 흐름은 원래도 선택 기능이었고
기본 경로가 아니었는데, 유지 비용(상태머신 복잡도)에 비해 실제로 완주하는 사용자가
있는지 확인할 방법이 없었다. 특히 매매일지가 유일한 사용자 행동 기록 수단이었는데, 그
기록조차 이 흐름을 완주해야만 남는 구조였다.

## 현재 상태

- 8단계 흐름 코드는 삭제하지 않고 `webapp/archive/precision_review.py`에 보존했다.
  이 파일은 `pages/` 밖에 있어 Streamlit이 자동으로 사이드바에 등록하지 않고, 어디서도
  import되지 않아 실행되지 않는다.
- 손절/익절 자동산출 로직(`lib/risk.py::compute_stop_take_profit`)은 파일 자체는
  남아있지만 위 아카이브 파일만 이걸 참조하며, 라이브 화면에서 호출되는 경로는 없다.
- 매매일지 저장 모듈(`lib/journal.py`)과 데이터 파일(`trade_journal.csv`)은 완전히
  삭제했다. 삭제 시점 데이터는 개발 테스트 기록 6건뿐이었고 실사용 데이터는 없었다.

## 재도입 시 필요한 작업

1. `webapp/archive/precision_review.py`를 `app.py`에서 import하고, Conflict Board에
   "정밀 검토 시작" 버튼을 되살려 상태 전환을 연결한다(구체적 방법은 그 파일 상단
   docstring에 적혀 있다).
2. 매매일지 저장/로드 함수(`append_entry`/`load_journal`)와 `trade_journal.csv`를 git
   이력(정밀 검토 제거 커밋 이전)에서 복원하거나 다시 작성한다.
3. 재도입 전 다시 확인해야 할 기존 한계: 트레일링 손절(나머지 50% 물량)은 계산 로직이
   없고 UI 문구로만 존재했다는 점, 매매일지가 Streamlit Cloud 재배포 시 파일 시스템
   초기화로 사라진다는 점(영속화 미해결)이었다는 점.
